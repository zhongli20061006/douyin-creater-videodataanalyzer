## 决策背景（产品事实）

- 项目最终目标是完整的开源项目与商业接单技术展示；
- 前端确定会有多个页面（看板、视频数据、收集任务、数据质量等）；
- 单用户本地工具，但代码质量与工程化程度是展示价值的组成部分；
- 用户已有多个同架构全栈项目经验。

## 主要组合（唯一主选）

**Vue 3.5（Composition API / `<script setup>`）+ Vite 8 + TypeScript + Vue Router + Pinia 3 + Element Plus 2.14 + Axios**

- 后端 FastAPI 保持不变；
- 生产：Vite 构建 `dist/`，由 FastAPI 静态服务；
- 开发：Vite dev server，`/api` 代理到 `http://127.0.0.1:8001`。

## 架构驱动

- 多页面共享状态（队列长度、爬虫状态、收集结果）→ Pinia；
- 工程化与组件化是展示价值 → 标准 Vite 工程 + Element Plus；
- 部署/运维简单（单机 FastAPI）→ 构建产物静态服务，不引入独立前端服务；
- 可维护性 → TypeScript + 目录规范。

## 已否决的候选

- **原生 HTML/JS 继续**：多页面共享状态与展示价值不足；
- **无构建（脚本式）Vue**：不符合工程化展示目标；
- **React**：用户倾向 Vue，且中文接单生态 Vue 更常见，无证据显示更优。

## 用户已确认的后果

- 现有 3 个原生页面将重写为 Vue 页面（含数据质量页）；
- 前端引入构建流程（`npm install` / `npm run dev` / `npm run build`）；
- 老页面在新应用就绪前保留，全部迁移完成后再切换根路径并清理。

## 迁移与再评估触发条件

- 迁移期：新 Vue 应用在 `/app` 下开发预览，根路径保持旧面板；
- 再评估触发：无当前已知触发条件；如出现复杂图表看板或多端需求，按新证据评估。
