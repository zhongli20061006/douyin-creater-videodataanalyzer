# 数据清洗功能设计

日期：2026-08-10
状态：设计已获用户确认，待用户审阅本文件
项目：抖音爬虫管理系统（douyinpachong）

## 1. 背景与目标

当前数据库有 182 条视频记录。曾发生「兜底数据覆盖已有完整记录」的问题（已修复为不完整数据只 INSERT IGNORE）。本功能的目标：

1. 数据质量在面板内可见（概览 + 问题清单）；
2. 一键修正 + 人工确认后删除问题数据；
3. 导出 CSV（Excel 可直接打开）；
4. 爬虫入库时自动过滤垃圾、保护已有数据。

## 2. 范围

### 本轮做

- 入库自动清洗规则（管道内）；
- 后端质量接口：报告 / 修正 / 删除 / 导出；
- 面板「数据质量」页面（简洁版，与现有静态前端一致）；
- 单元测试 + 真实库集成验证。

### 本轮不做

- 前端全面改版（属于另一条工作线）；
- 定时自动清洗或提醒；
- 数据库结构变更（不加状态列等）；
- 新增第三方依赖（CSV 用标准库，pandas 已安装）。

## 3. 清洗规则

### 报告分类（扫描全库，只读）

- **疑似无效**：标题为空且作者为空，或统计全零且标题为空；
- **占位页标题**：标题含「在抖音记录美好生活」等无效页特征；
- **陈旧未更新**：`update_time` 距今超过 90 天（默认阈值，可调）。字段语义说明：`update_time` 是记录最近一次被爬虫成功入库/更新的时间（表结构 `ON UPDATE CURRENT_TIMESTAMP`），**不是视频发布时间**（`publish_time` 才是）。因此该分类表示「这条视频很久没有被重新爬取过」，提示数据可能过时、建议重新爬取，而非「视频本身很旧」。若将来需要按视频发布时间判断旧内容，应基于 `publish_time`，不与此分类混用；
- **作者缺失但标题完整**：保留，仅提示，不删除。

说明：

- `play_count=0` 是抖音常态，不算问题；
- `video_id` 有唯一约束，行级重复当前不存在。重复检测逻辑明确定义为：报告同时计算 `COUNT(*)` 与 `COUNT(DISTINCT video_id)`，若不一致，则按 `GROUP BY video_id HAVING COUNT(*)>1` 列出重复的 `video_id`。该检查用于防御未来可能绕过唯一约束的入库方式（如外部手工导入），当前预期恒为一致。

### 自动过滤（入库时，管道内）

- 标题和作者都为空 → 不建行；
- 占位页标题 → 不建行；
- 标题写入前去除首尾空白与换行；
- 兜底（incomplete）数据 → INSERT IGNORE，不覆盖已有记录（已完成）。

### 修正（安全规范化）

- 仅做无争议的字段规范化：标题去空白/换行；
- 不做有歧义的改写。

### 删除（需人工确认）

- 只删除用户在界面勾选并确认的行（疑似无效 / 陈旧类）；
- 后端二次校验：删除时**重新读取当前库内该行最新数据**并按可删规则重新判定（不依赖报告快照）。若在报告生成到用户确认之间该行已被修正/补全（如标题被手动填上、统计被更新）而不再满足可删规则，则拒绝删除该行。
- 单次删除数量上限：最多 200 个 video_id，超限返回 400 并提示分批操作。

## 4. 后端接口

- `GET /api/quality/report` → 概览 + 问题清单（video_id、类型、原因、标题、作者等）；
- `POST /api/quality/fix` → 执行安全修正，返回受影响行数；
- `POST /api/quality/delete`（body: `{"video_ids": [...]}`）→ 校验后删除，返回删除数与拒绝数；
- `GET /api/quality/export?scope=all|issues` → CSV（UTF-8 BOM），Excel 直接打开不乱码。使用标准库 `csv` 模块生成，字段按标准转义（含逗号/换行/引号时用双引号包裹，内部引号加倍），确保标题等含特殊字符的字段不会错列。

## 5. 前端页面

- 新增 `frontend/quality.html` + `frontend/quality.js`，风格与现有暗色面板一致；
- 概览卡片：总数、作者数、最近爬取、问题数；
- 问题清单表格：可勾选、按类型查看；
- 操作按钮：一键修正 / 删除选中（二次确认）/ 导出 CSV；
- 勾选删除交互：单次勾选上限 200 条，超过上限时阻止并提示分批选择（与后端限制一致）。
- 在 `index.html` 增加导航入口。

## 6. 测试策略（TDD）

- 单元测试：清洗规则（标题规范化、空记录判断、占位页判断）、报告统计、CSV 生成；
- CSV 测试覆盖含逗号、换行、引号的标题字段，断言转义正确；
- 删除接口测试覆盖「报告生成后行数据被修正 → 删除被拒绝」的时间窗口场景；
- 集成验证：真实库跑报告、修正、删除一条测试行、导出文件内容校验；
- 回归：现有测试（当前 15 个）保持通过。

## 7. 实施阶段

1. 入库自动过滤（管道 + 单元测试）；
2. 后端质量接口 + 导出（API + 单元测试）；
3. 面板数据质量页（对接接口 + 手动验证）。

每阶段完成即验证，全部完成后统一提交。

## 8. 安全与数据保护

- 删除必须人工确认，接口二次校验；
- 导出仅含业务数据（Cookie、密码等敏感值本就不在库里）；
- 不触碰现有数据库结构，不修改现有爬取接口。

## 9. 默认值与可调项

- 「陈旧未更新」阈值默认 90 天，集中在配置常量，便于调整；
- 导出格式默认 CSV（UTF-8 BOM）；如需原生 xlsx 可后续扩展。
