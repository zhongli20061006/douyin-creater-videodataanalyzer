# 抖音个人视频数据分析器 - 采集计数/手动停止 + id 链路修复设计

日期：2026-08-11
状态：已按用户拍板的设计确认（停止语义 A：已采数据照常入库、id 照常保留；不做目标条数输入），待用户复核本 spec
前置设计：`docs/superpowers/specs/2026-08-11-personal-analyzer-extension-collection-complete.md`（采集完善，本设计为其交互与 id 链路的补充修复）

## 1. 背景与问题

真实使用中发现两个问题：

1. **大主页采集无法提前终止且无进度反馈**：博主主页可能上千条视频，但用户往往只需一部分；当前采集开始后按钮被禁用、无实时计数，只能等自然结束（上限 1000 或滚动到底）。
2. **video_ids.txt 里的 id 与"新采集"对不上**：逐段排查后确认链路存在两个真实缺陷：
   - 插件在采集循环**完全结束后**才一次性 `POST /api/extension/ids`，一次提交全部 id；后端单次上限 100 条，超过 100 条整批 400 拒绝 → 大主页（如 128 卡片主页）视频数据入库了，但 id 一条都存不进去；
   - ids 只在结束时上报一次，中途停止/页面报错/SPA 切页时该调用不会执行 → 已采到的 id 整轮丢失。
   - 另外文件语义为"去重累加、保留历史"，当前 130 行 = 平原公子 60（历史遗留）+ 黑白阿巴巴 39（新采集）+ 成都中医药大学小杨学长 31（新采集），混合属设计如此，本轮不改变文件格式。

## 2. 目标（本轮做）

- 采集过程中**实时显示已采集条数**（「采集中 N 条」，每轮更新）；
- 提供**手动「停止」按钮**：停止滚动，但已采集数据照常分批入库、id 照常保留（用户拍板语义 A）；
- 修复 id 链路：**按批（≤100）增量上报 id**，大主页不再被整批拒绝，停止/出错时已采 id 已落盘；
- 全程 TDD：可测纯逻辑先 RED 后 GREEN，DOM/状态接线用 jsdom 冒烟 + 真机验收。

## 3. 决策点（用户已拍板）

### 决策 A：停止语义
- **已确认**：手动停止 = 不再继续滚动，已采集数据照常入库、id 照常保留；一条未采到时直接取消（不入库、不报 id）。

### 决策 B：是否加目标条数输入
- **已确认**：不加。只做「实时计数 + 手动停止」，保持交互最少。

### 决策 C：UI 形态
- **采用**：右下角按钮升级为按钮组——主按钮采集时显示「采集中 N 条」，旁边出现红色「停止」按钮；结束/停止后复位。
- 备选（被拒）：独立进度面板（遮挡更多）；采集时点主按钮弹确认停止（易误触且当前按钮禁点）。

## 4. 实现设计

### 4.1 实时计数 + 手动停止（collect.js）

- 按钮区：`dy-analyzer-btn` 升级为容器，内含主按钮 + 停止按钮（默认 `display:none`）。
- 采集开始：`stopRequested = false`；主按钮文案「采集中 0 条」；停止按钮显示。
- 计数更新：每轮解析完卡片后 `btnText = '采集中 ' + seen.size + ' 条'`。
- 停止触发：点击停止 → `stopRequested = true`，停止按钮立即置「已请求停止」态并防重复点击。
- 循环响应：
  - 循环条件追加 `!stopRequested`；
  - `sleep(ms)` 改为可中断（轮询 100ms 检查标志提前 resolve）；
  - `waitForGrowth` 的 300ms 定时器回调同时检查标志 → 停止响应在 1 秒内；
- 停止后流程：跳出滚动循环 → 仍按现有逻辑分批上报视频 + 每批上报 ids（见 4.2）→ toast「已手动停止：成功 X 条…」。
- 边界：
  - 停止时 `seen.size === 0`：直接取消，toast「已取消，未采集到数据」，不上报；
  - 重复点击停止：忽略；
  - 自然结束/出错：toast 文案与现状一致，按钮复位。

### 4.2 id 链路修复（collect.js + 纯函数）

- 把「结束一次性 reportIds([...seen])」**删除**，改为**每批视频数据上报后，立即上报该批对应的 video_id 列表**（每批 ≤ 100，天然满足后端 `MAX_BATCH=100` 上限）。
- 新增可测纯函数（放入 `extension/content/parse.js`，Node 测试共用）：
  - `idsFromBatch(records)`：从一批记录中提取去重后的 video_id 数组（≤100）；
  - `progressLabel(count)`：`0 → '采集中 0 条'`，`39 → '采集中 39 条'`。
- id 上报失败：仅 `console.warn`，不中断主流程、不做自动重试（MVP 范围外）。
- 停止/出错时：已结束的批次已各自上报 ids，故已采 id 不丢失（满足语义 A）。
- 服务端 `append_ids_file` 去重/锁/原子替换逻辑不变，接口契约不变。
